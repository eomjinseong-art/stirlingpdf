📖 Stirling-PDF 분석: 왜 무거울 수밖에 없었을까?

온라인에는 수많은 PDF 툴이 존재하지만, 보안 우려나 과도한 광고 때문에 실무에서 마음 놓고 쓰기 어려운 경우가 많습니다. 이때 전 세계 개발자들 사이에서 유명한 오픈소스가 바로 Stirling-PDF입니다.

이 프로그램은 PDF 합치기, 변환, OCR 문자 인식, 서명 등 온갖 기능을 한곳에 모아둔 거대한 백화점 같은 솔루션입니다.

💡 핵심 요약: Stirling-PDF는 보안성이 뛰어난 만능 PDF 도구이지만, 그만큼 몸집이 상상 이상으로 거대합니다.

치킨 한 마리를 튀겨 먹으려고 부엌에 가스버너를 켜는 상황을 떠올려 봅시다. 그런데 라면 하나를 끓이겠다고 전 세계에서 가장 거대한 대기업 주방 설비와 대형 오븐, 식기세척기까지 통째로 트럭에 싣고 원룸에 밀어 넣으려는 시도가 바로 Stirling-PDF를 무료 서버에 그대로 올렸을 때의 상황입니다.

내부적으로 자바(Java) 런타임을 구동하고, 문서 변환을 위해 LibreOffice를 돌리며, 이미지 글자 인식을 위해 Tesseract OCR 엔진까지 동시에 띄우기 때문에 최소 1GB~2GB 이상의 막대한 RAM을 요구하게 됩니다.

💡 핵심 요약: 가벼운 작업에 너무 무거운 패키지들을 동시에 구동하는 구조라, 512MB 제한의 무료 서버에서는 버텨낼 재간이 없습니다.

🚀 아키텍처 구축 가이드: 비용 0원 방어 전략

서버 유지비용을 단 1원도 쓰지 않으면서(Zero-Cost), 대규모 트래픽에도 끄덕 없는 시스템을 만들기 위해 우리는 현대 웹 개발의 핵심인 디커플링(Decoupling, 역할 분리) 아키텍처를 도입했습니다.

사용자가 접속해서 화면을 마주하는 앞마당(프론트엔드)과, 백그라운드에서 파일을 처리하는 주방(백엔드)을 완전히 분리하여 각각 최적의 무료 클라우드에 배치했습니다.

💡 핵심 요약: 화면과 서버를 완벽하게 분리하여 각각 무료 호스팅 플랫폼에 배치함으로써 고정 비용을 0원으로 방어했습니다.

구체적인 3단계 구축 절차

  1. 프론트엔드 배포 (Vercel): 사용자가 마주하는 웹 화면(HTML/JS)을 전 세계에서 가장 안정적인 정적 호스팅 서비스인 Vercel에 배포합니다.
  2. 초경량 백엔드 구축 (Render): 파이썬의 초경량 웹 프레임워크인 Flask와 PDF 전문 라이브러리 PyPDF만 결합하여 메모리를 50MB 이하로 소모하는 미니 서버를 Render에 올립니다.
  3. API 통신 연동: 웹페이지에서 사용자가 파일을 올리면 자바스크립트가 Render 백엔드 API로 데이터를 전송하고, 처리된 파일을 안전하게 받아오도록 CORS 통로를 연결합니다.
💡 핵심 요약: Vercel과 Render 조합을 통해 서버 비용 부담 없이 전문가 수준의 웹 서비스 인프라를 구축했습니다.

🔥 심층 트러블슈팅 일지: OOM 지옥 탈출기

처음부터 이 아키텍처가 완성된 것은 아닙니다. 첫 배포를 감행했을 때, Render 무료 티어의 물리적 한계에 부딪혀 서버 콘솔창에 다음과 같은 치명적인 에러가 찍혔습니다.

Exited with status 1 while building your code.
ERROR: Ran out of memory (used over 512MB) - Server Crashed.
# 512MB RAM 제한을 초과하여 자바 기반 모놀리식 서버가 즉시 다운된 상황

서버가 켜지자마자 메모리 부족으로 기절해 버리는 OOM(Out of Memory) 지옥이었습니다. 이 난관을 극복하기 위해 세 가지 갈림길을 놓고 치열하게 고민했습니다.

시행착오 속에서 검토한 3가지 전략

  • 전략 1 (유료 플랜 전환): 월 7달러짜리 서버로 업그레이드 $\rightarrow$ 가장 속 편하지만 "비용 0원 창업"이라는 우리의 철학과 원칙에 위배됩니다.
  • 전략 2 (오라클 클라우드 프리티어): 24GB RAM을 주는 무료 VPS 활용 $\rightarrow$ 스펙은 매력적이지만 까다로운 가입 심사와 초기 리눅스 세팅 리스크가 큽니다.
  • 전략 3 (초경량 커스텀 백엔드 직접 구현): 무거운 오픈소스를 과감히 버리고, 우리에게 필요한 핵심 기능만 파이썬으로 가볍게 재구축 $\rightarrow$ 최종 채택 및 성공!
💡 핵심 요약: 무거운 프로그램을 억지로 맞추려 하기보다, 본질에 집중해 코드를 직접 가볍게 짜는 실용주의적 선택이 주효했습니다.

결국 전략 3을 통해 며칠간의 고민을 해결하고 쾌적한 초경량 서버를 완성했습니다. 이 과정을 통해 기술적 장벽에 부딪혔을 때 몸집을 가볍게 다이어트하는 유연함이 곧 사업의 성패와 속도를 결정한다는 소중한 인사이트를 얻었습니다.
