📖 [개발일지] Stirling-PDF와 Render 무료 티어 OOM 지옥 탈출기

1. 마주한 문제: "Ran out of memory (used over 512MB)"

무료 호스팅(Render) 환경에서 오픈소스 PDF 솔루션인 Stirling-PDF를 도커(Docker)로 띄우려 시도했다. 하지만 서버가 켜지자마자 OOM(Out of Memory) 에러를 뿜어내며 곧바로 다운됐다.

원인: Stirling-PDF는 자바(Java), LibreOffice, Tesseract OCR 등 무거운 패키지가 통째로 묶여 있는 모놀리식 구조라 최소 1~2GB 이상의 RAM이 필수적이었다. 무료 서버의 512MB 한계로는 물리적으로 구동이 불가능했다.

2. 해결을 위한 3가지 전략 검토

  • 전략 1 (유료 전환): 월 $7의 Hobby 플랜으로 업그레이드 $\rightarrow$ 가장 편하지만 완전 무료 기조에 위배됨.
  • 전략 2 (오라클 클라우드): 24GB 무료 VPS 활용 $\rightarrow$ 강력하지만 까다로운 가입 심사와 리눅스 초기 세팅의 스트레스.
  • 전략 3 (초경량 커스텀 백엔드): 핵심 기능(합치기)만 뽑아 파이썬(Flask + PyPDF)으로 직접 구현 $\rightarrow$ 최종 선택!

3. 아키텍처 재조정과 실천

시간은 가장 소중한 자산이다. 무리하게 무거운 오픈소스를 고집하기보다, 비즈니스 목적에 맞게 몸집을 극단적으로 다이어트한 파이썬 백엔드를 구축해 Render 무료 티어(512MB)에 안착시켰다.

# 초경량 백엔드 핵심 로직 (Python Flask)
from flask import Flask, request, send_file
from pypdf import PdfMerger
import os

app = Flask(__name__)
@app.route('/merge', methods=['POST'])
def merge_pdfs():
    files = request.files.getlist('files')
    merger = PdfMerger()
    for file in files:
        merger.append(file)
    output_path = "/tmp/merged.pdf"
    merger.write(output_path)
    merger.close()
    return send_file(output_path, as_attachment=True, download_name="merged.pdf")
